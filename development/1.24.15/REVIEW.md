# PlazCode 1.24.15 development — ClickUp provider

Private test build only. Do not publish or change update feeds without explicit approval.

## Scope
ClickUp Ask Brain and existing AI-agent direct messages, using the existing PlazCode Studio, Blender and local-file commands. The PlazCode bar follows the active composer and clears Ask/Agents tabs on the landing screen. Human chats, task comments, Docs and agent-creation forms are excluded. The desktop provider list opens the generic ClickUp site without embedding a private workspace ID.

## Implemented
ClickUp host permissions and SPA-scoped provider; exact Quill draft insertion; one exact Send click with a user-message receipt; scoped Send/Stop; avatar-based roles and stable thread identity; screenshot uploads and feedback; compact list_commands startup. No guessed form submissions, model-picker changes or automatic replay after ambiguous delivery. Native ClickUp task/Doc/agent tools cannot stand in for local PlazCode commands. All pre-existing provider function bodies and the merged Studio, Blender, dashboard and Skills behavior are preserved; desktop HTML changes are limited to one supported-AI entry and its count.

## Test build 2 — startup, placement, lock removal and donations
- Reproduced the real ClickUp failure: the native failed-message label explicitly rejected the oversized command reference as too long. An optimistic UUID row is not a receipt. Native accepted messages receive numeric IDs; confirmation now requires one of those IDs and a rich-text-normalized content match. A native rejection is reported explicitly, and ambiguous sends still never replay automatically.
- ClickUp alone opts into lossless startup staging: command-reference/user-preference context is split at conservative 10,500-character boundaries, each intermediate part must receive its exact acknowledgement, and only the final readiness acknowledgement enables the session. Original instructions are not truncated. The 18,000-character pre-send guard is a conservative PlazCode bound, not a claim about ClickUp's exact limit. Oversized later tool results must be paged/reduced rather than silently sent or replayed.
- A failed or incomplete startup cannot restore Ready from a system marker. Injected rows retain provider-owned masking even if Angular resets PlazCode's class. The bar is anchored to the actual rounded input, not the full-width custom-element wrapper; a lower-edge cutout preserves native Ask/Agents painting and hit testing. The collapse control has its own non-overlapping position.
- Live signed-in Ask Brain, with all native tool execution disabled: initial list_commands and two bounded context parts were accepted, the intermediate acknowledgement matched, the final reply was exactly "PlazCode is ready.", no native failed labels appeared, and all injected user-message bodies were hidden. The live bar matched the 680px conversation composer and stayed 8px above it. Landing Ask and Agents buttons both passed hit testing. The temporary debug overlay was removed afterwards.
- Chromium production-core fixtures cover Ask Brain and agent DMs, larger multipart startup with lossless Unicode reconstruction, automatic mock Studio/Blender/file commands, native rejection, Markdown-normalized receipts, persistent masking, incomplete-handshake recovery, no replay after uncertainty, exact donation links and non-overlapping toolbar controls. Firefox runs the same fixture in private CI.
- Condo Lock is removed from the shared core for every supported provider: no classifier, strike recording, cooldown, start/send/tool/Co-work lock gate or lock UI. A migration removes old stored lockout state and old lock panels. Unrelated ToolGuard, Ask approvals, Stop and provider moderation remain unchanged.
- All four Robux donation destinations use the supplied replacement URLs and immediately visible labels: 50, 100, 500 and 1,000 Robux. Failed price lookups can no longer blank or overwrite these configured amounts. The new desktop Donations navigation entry is immediately after Templates and before Terminal, with Small/Medium/Large/Massive headings and the URL on the next line. Fixed native IPC targets open the OS default browser; ordinary browser-hosted dashboards retain actual safe new-tab links. No payment is initiated automatically.
- Donation regressions check exact URLs/amounts, navigation order, all four headings, native IPC interception and current-browser fallback. A local Chromium rendering verifies the actual page navigation and layout. Native Rust tests cover the fixed donation allowlist and reject unknown/arbitrary targets. No existing donation destinations were found outside the shared settings renderer; the new desktop page uses the same four replacements.
